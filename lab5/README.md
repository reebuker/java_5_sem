# Лабораторная работа 5

Вариант 8, пульты управления.

## Сборка и запуск

Нужны Java 21 и Maven.

    cd lab5
    mvn package
    java -jar target/main.jar --help

Программа запускается с ключами, без ключей она печатает справку.

| ключ | что делает |
|------|------------|
| `--help`, `-h` | справка |
| `--show` | один раз вывести состояние пультов из файла |
| `--menu` | меню, как в ЛР4: файл читается при запуске, изменения сразу сохраняются в него |
| `--replace <файл>` | заменить рабочий файл этим, старое содержимое пропадает |
| `--watch` | показывать пульты снова и снова, каждый раз перечитывая файл, остановка по Ctrl+C |
| `--export <журнал>` | каждый период дописывать в журнал (csv) состояние пультов с временем |
| `-p`, `--period <сек>` | как часто повторять, от 1 до 3600, по умолчанию 2, для `--watch` и `--export` |
| `-f`, `--file <файл>` | файл с пультами, по умолчанию `data.csv` |

Режим нужен ровно один. Значение можно писать и через пробел, и через равно
(`-p 5`, `--period=5`). Если среди ключей есть `--help`, печатается справка и всё
остальное не проверяется. При неправильных ключах программа пишет, что не так
(и подсказывает похожий ключ, если ошиблись в букве), и выходит с кодом 2.
Коды выхода: 0 всё хорошо, 1 файл не прочитался или не записался, 2 неправильные ключи,
3 внутренняя ошибка программы (она пишет короткое сообщение, а не трассировку).

Примеры:

    java -jar target/main.jar --show
    java -jar target/main.jar --show -f broken.csv
    java -jar target/main.jar --menu -f data.csv
    java -jar target/main.jar --replace broken.csv -f work.csv
    java -jar target/main.jar --watch -p 1 -f work.csv
    java -jar target/main.jar --export log.csv -p 5 -f work.csv

`--replace` сначала читает новый файл и, если в нём есть хотя бы один пульт,
копирует его рядом с рабочим и атомарно подменяет, так что другая программа,
которая читает рабочий файл, видит или старый файл, или новый целиком. Если нового
файла нет или в нём нет пультов, ничего не меняется и код выхода 1.

`--watch` работает в отдельном потоке (`Poller`, это `Runnable`): раз в период он
читает файл заново в новую базу, старая забывается, и печатает состояние пультов.
Поэтому, если в другом терминале сделать `--replace` или поменять файл, при
следующем тике будет видно новое. Если файла на время нет, тик пишет ошибку
и работа продолжается. По Ctrl+C главный поток прерывает поток через `interrupt()`
и ждёт его через `join()`, потом пишет «Остановлено».

`--export` работает на том же `Poller`: каждый период читает файл с пультами заново
и дописывает в журнал по строке на каждый пульт. Журнал только дописывается
(шапка пишется, если файл новый или пустой), поэтому можно останавливать и запускать
снова. Журнал не может быть тем же файлом, что и база, иначе строки журнала попали бы в базу.
В журнал идут только свойства, которые меняются во время работы, а производитель,
модель и тип батареек не меняются и туда не попадают:

    time,id,type,batteryLevel,on,volume,position,appliances,extra1,extra2
    2026-11-13 19:25:25,0,TvRemote,87,true,35,3,,1,0
    2026-11-13 19:25:25,2,SmartHomeRemote,92,true,,,101,2,-1

Столбцы те же, что в файле с пультами (`position` это канал или трек,
`appliances` приборы умного дома, `extra1` и `extra2` счётчики пульта), только
в начале добавлено время, а `id` это номер пульта в базе в этот момент.

В меню при запуске пульты читаются из файла (если файла нет, список пустой и файл
появится при первом изменении). После каждого изменения (добавить, удалить,
изменить, любая кнопка пульта) база сразу записывается в этот же файл, поэтому
`--watch` и `--export` в другом терминале видят изменения почти сразу. Пункт 6
заменяет все пульты теми, что лежат в другом файле (старые забываются), и дальше
сохранение идёт уже в него. Пункт 7 записывает пульты в другой файл и тоже
переключается на него. В broken.csv лежат кривые строки для проверки терпимого
чтения, при сохранении из меню они пропадают, остаются только нормальные пульты.

Не надо делать `--replace` для файла, который сейчас открыт в меню: меню держит
пульты в памяти и при следующем изменении запишет их поверх новой базы.

## Если что-то не так

Программа не должна падать от неправильного ввода, ключей или файлов, вместо этого
она пишет, что случилось, и живёт дальше:

- меню принимает любой ввод: нечисла, огромные числа, пустые строки, управляющие
  символы, обрыв ввода (Ctrl+D) и кривые байты; имя и модель пульта не длиннее 20 символов
  и без управляющих символов; имя файла, которое нельзя превратить в путь, отклоняется;
- причина неудачи с файлом пишется по-русски в скобках: нет такого файла, нет доступа,
  это не обычный файл (например, папка), файл больше 8 МБ, в него нельзя писать;
- если файл при запуске меню не прочитался (папка, слишком большой, нет доступа),
  автосохранение выключается, над меню об этом написано, и файл не затирается;
  сохранение включится, когда пункты 6 или 7 успешно выберут другой файл;
- в файле читается не больше 10 000 пультов и 8 МБ, лишнее пропускается;
  числа вне допустимых значений заменяются умолчанием, а сломанные строки пропускаются
  (сколько чего пропущено, пишет `--show` и пункт 6);
- запись идёт через временный файл и подмену, права старого файла и символьная ссылка
  сохраняются; новый файл создаётся с обычными правами;
- `--watch` и `--export` сами останавливаются, если вывод закрыли (`... | head`), а
  сбой одного тика (нет файла, нельзя записать журнал) не останавливает работу.

## Структура (MVC)

    src/main/java
    ├── app/Main.java                    собирает три части вместе, отдаёт ключи контроллеру
    ├── model/                           Model: данные и правила, ничего не печатает
    │   ├── RemoteRepository.java        все пульты в памяти, выдаёт id
    │   ├── remote/                      пульты (Remote и три вида), RemoteState, ActionResult
    │   ├── device/                      устройства (Tv, Stereo, SmartHome)
    │   └── storage/                     csv: Csv, CsvStorage (база пультов), LogWriter (журнал)
    ├── view/ConsoleView.java            View: весь вывод и ввод в консоли
    └── controller/                      Controller: решает, что делать
        ├── ArgsParser.java              разбор ключей командной строки
        ├── AppController.java           запускает режим по ключу (help, show, menu, replace, watch, export)
        ├── Poller.java                  задача «делать что-то каждые N секунд», Runnable
        ├── MenuController.java          главное меню, список пультов, файл
        └── RemoteController.java        работа с одним пультом

Поток такой: контроллер спрашивает выбор у view, меняет модель и просит view
показать результат. View только показывает модель и ничего в ней не меняет,
а в модели и контроллере нет System.out и Scanner.

## Файл с пультами

Одна строка это один пульт, первая строка с названиями столбцов необязательна.
Столбцы по порядку:

    type,manufacturer,model,batteryType,batteryLevel,on,volume,position,appliances,extra1,extra2

- type: TvRemote, StereoRemote или SmartHomeRemote
- position: номер канала или трека, appliances: приборы умного дома, например 101
- extra1 и extra2: свои поля пульта (у телевизора прошлый и случайный канал)
- пустое или кривое значение заменяется умолчанием, строка неизвестного типа пропускается
